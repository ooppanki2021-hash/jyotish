# Резюме проекта «Джйотиш 2» — для следующего помощника

Это рабочая копия всего проекта: сайт (он же Pages), приложение для Android (WebView-обёртка над этим же сайтом),
генераторы печатных календарей и скрипт сборки APK. Прочти этот файл целиком, прежде чем что-то менять.

## 1. Что за продукт
- Сайт: корень репозитория = файлы сайта. GitHub Pages: https://ooppanki2021-hash.github.io/jyotish/ (деплой с main автоматически).
- Приложение: package `ru.jyotish.app2`, название «Джйотиш 2», minSdk 24, target 34. Внутри — WebView, который открывает assets (те же файлы сайта). Весь код — JavaScript в assets, нативная часть только MainActivity.java (apk-src/).
- Репозиторий: github.com/ooppanki2021-hash/jyotish, ветка main. Второй репозиторий ooppanki2021-hash/apk — старый toolkit, не нужен для текущей работы.

## 2. Железные правила пользовательницы (нарушать нельзя)
1. Никакого санскрита в интерфейсе и календарях. Термин можно только в скобках после русского названия. Титхи → «N-е лунные сутки, Луна растёт/убывает»; Раху-кала → «плохое время»; Абхиджит → «окно удачи».
2. Настенный лист календаря = только заголовок «месяц год» + клетки. Никаких легенд и подвалов на листе.
3. Памятка «как читать» — ОТДЕЛЬНЫЙ 13-й файл комплекта у ОБОИХ календарей (джйотиш и дараган). В app-сборке добавляется автоматически.
4. Готовые комплекты отдавать ПАПКОЙ с отдельными PDF (архив — только как необязательное дополнение).
5. В мухурте показывать только её лично-зелёные даты; окна не должны раздувать строку: одно лучшее окно видно, остальное по тапу/в деталях.
6. Дараган-календарь (настенный) = утверждённый формат мухурты: зелёные строки «тема: часы (аспект)», красные сгруппированные «не начинайте новое: темы — причина», ⚠-строки, серая строка «мухурта Дарагана: тем с поддержкой — N». Цветные списки сфер для Дарагана НЕ предлагать (отклонено дважды).
7. Обновления приложения — только подписанные её ключом (см. §5) и только с ростом versionCode/versionName. Последняя подготовленная подписанная сборка: 2000000000 / 2.114 (18.10.2026). Следующая: 2000000001 / 2.115. Установка новой версии пользователем пока не подтверждена.
8. Про токен GitHub НЕ напоминать (она закрыла тему). Токен выдаёт она сама под конкретный пуш; после пуша вернуть remote на URL без токена.
9. Файлы-артефакты отдавать в чат через показ файла (APK, архивы); папки пользовательница видит в рабочей области.

## 4. Структура репозитория
- `/` — сайт: index.html, style.css, js/ (движки и UI), img/.
- `js/calendar-pdf.js` — джйотиш-календарь: drawMonth (клетки), drawInstructionJyotish (памятка), buildYear (12 листов + 13-й файл).
- `js/calendar-daragan.js` — дараган-календарь (формат мухурты, customLines) + его памятка drawInstruction.
- `js/muhurta.js` — панчанга-мухурта: ACTIVITIES (8 тем), окна дня, findNextMuhurta; в computeDay есть tithiNum.
- `js/daragan.js` — метод Дарагана: THEME (9 тем ВКЛЮЧАЯ карьеру — вернули по её просьбе), themeWindows (мягкие аспекты Луны, орб ≤1.5°).
- `js/app.js` — UI: вкладки, мухурта (personalForDay: Юпитер +2/+1, Сатурн −2/−1, Луна +3/−3/+1 от её Луны; зелёный порог ≥2), лента «по дням» (buildFeed), сборка календарей (onCalendarPdf), THEME_MAP мухурта→дараган (business→career).
- `tools/` — генераторы печатных комплектов (не входят в assets приложения, кроме app-bridge.js и build_cities.py):
  - `tools/daily.js` — расчёт дней джйотиш-календаря (node, UMD).
  - `tools/make_calendar_pdf.py` — рендер 12 листов джйотиш (fpdf2).
  - `tools/jyotish-set/instr_jyotish.py` — памятка джйотиш (fpdf2), аргумент: каталог вывода.
  - `tools/daragan-set/gen_set.js` + `render_set.py` — 12 листов + памятка Дарагана.
  - см. `tools/README.md` с командами.
- `apk-src/` — сборка APK: MainActivity.java, AndroidManifest.xml (шаблон с @VC@/@VN@), icon_src.png, build_apk.sh.

- Семейные debug-ключи (cert 74a7e333…) для финальных сборок НЕ использовать — обновление не встанет поверх её приложения.

## 6. Сборка APK (коротко)
`KSPASS=<пароль> bash apk-src/build_apk.sh 2000000001 2.115 /путь/jyotish2.keystore /путь/out.apk`
Скрипт сам скачает build-tools r33.0.1 и android.jar (platform-30), соберёт assets из корня репозитория, подпишет и проверит.
Подводные камни ручного пути: aapt не создаёт каталоги пакета — нужен `mkdir -p gen/ru/jyotish/app2`; javac обязательно с `-encoding UTF-8`; d8 может молча выйти без dex — проверять `test -f bin/classes.dex`; после snapshot-ов окружения у bt/ слетают права и часть файлов — лечится `chmod -R +x` или повторным скачиванием build-tools_r33.0.1-linux.zip.

## 7. Печатные комплекты (регенирация)
Нужны pip-пакеты: fpdf2, pypdfium2 (для проверок-превью).
- Джйотиш: `node tools/daily.js --out year.json --by 1984-04-27 --bt 00:40 --btz 4 --lat 43.02 --lon 44.68 --from 2026-10-01 --to 2027-09-30 --lat2 43.02 --lon2 44.68 --tz2 3`, затем `python3 tools/make_calendar_pdf.py --data year.json --outdir OUT`, затем `python3 tools/jyotish-set/instr_jyotish.py OUT`. Имена файлов: jyotish-calendar-YYYY-MM.pdf + jyotish-calendar-13-как-читать.pdf.
- Дараган: `cd tools/daragan-set && node gen_set.js && python3 render_set.py` (set/ = 12 месяцев + памятка).
- Комплект = 13 файлов; отдавать папкой.
- make_calendar_pdf.py восстановлен по утверждённому комплекту: содержимое и стиль совпадают, переносы отдельных строк могут отличаться на доли мм от отпечатанного тиража окт.2026 — это норма, не регрессия.

## 8. Контракты, которые нельзя ломать
- customLines в drawMonth: день = {d, vara, stars, lunarText, customLines:[{kind:'good'|'bad'|'mid',text}], timeLine, events:[]}; тонировка клетки по наличию good/bad; у дней с customLines нет spheres — все обращения к spheres обязаны быть с `|| []`.
- Памятки обоих календарей — 8 нумерованных пунктов, структура утверждена; править только по явной просьбе.
- Лента «по дням» (buildFeed): тема зелёная, только если есть окно панчанги И личный счёт ≥2; красная при личном ≤−2.
